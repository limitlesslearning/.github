# Support

## Where to get help

| Need | Where |
| --- | --- |
| Questions and first ideas | [Discussions on docs](https://github.com/limitlesslearning/docs/discussions) — start here before opening an issue |
| Product vision, Klados Handbook, roadmap | [Docs site](https://limitlesslearning.github.io/docs/) |
| Work tracking | [Org project board](https://github.com/orgs/limitlesslearning/projects/1) |
| Bug reports & feature requests | Open an issue with the matching template in the relevant repo, after a discussion if the work is not yet agreed |
| Content / docs proposals | Issue template **Content proposal** (or PR against [`docs`](https://github.com/limitlesslearning/docs)) |
| Design / architecture decisions | Issue template **RFC / decision proposal** |
| Security vulnerabilities | [SECURITY.md](./SECURITY.md) — private report only |
| Code of Conduct | [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md) |

## Before you open an issue

1. Search existing issues and the [project board](https://github.com/orgs/limitlesslearning/projects/1).
2. Check the [Decision log](https://limitlesslearning.github.io/docs/decisions/) — locked decisions are not reopened without new evidence.
3. For questions or first ideas, start a [discussion](https://github.com/limitlesslearning/docs/discussions). Use an issue form only for agreed work or a clear bug, so labels and triage stay accurate.

## Response expectations

Maintainers triage by priority (see [CONTRIBUTING.md](./CONTRIBUTING.md)):

| Priority | Typical first response |
| --- | --- |
| P0 – Critical | Within 1–2 business days |
| P1 – High | Within 1 week |
| P2 – Medium | Best effort during active phase work |
| P3 – Low | Backlog; no committed SLA |

Phase 0 focuses on documentation. Product (`platform`) support grows as that repository ships.

## What we do not provide

- Private 1:1 tutoring or career counseling via GitHub
- Guarantees for third-party content linked from the knowledge graph
- Support via personal email
