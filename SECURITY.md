# Security Policy

## Supported versions

Security updates apply to the default branch (`main`) of each public repository in the `limitlesslearning` organization.

## Reporting a vulnerability

**Do not open a public issue for security vulnerabilities.**

Report privately using one of these channels:

1. **GitHub private vulnerability reporting** — on the affected repository, open **Security → Report a vulnerability** (preferred when enabled).
2. **Maintainer contact** — message [@capsmagick](https://github.com/capsmagick) on GitHub. Do not send personal email.

Please include:

- Affected repository and, if known, commit or release
- Description of the issue and impact
- Steps to reproduce or a proof of concept
- Any suggested remediation

## What to expect

| Step | Expectation |
| --- | --- |
| Acknowledgement | Within **3 business days** |
| Initial assessment | Within **7 days** for P0/P1 severity triage |
| Fix / advisory | Coordinated privately; public disclosure after a fix is available or risk is accepted |

We may ask for clarification or a minimal reproduction. Please keep the report confidential until we publish a fix or advisory.

## Safe harbor

We will not pursue legal action against researchers who:

- Make a good-faith effort to avoid privacy violations, destruction of data, and service disruption
- Report the vulnerability promptly and privately
- Give us reasonable time to remediate before public disclosure

## Out of scope

- Social engineering of maintainers or community members
- Denial-of-service against third-party infrastructure we do not control
- Issues in dependencies with no realistic exploit path in our usage (still welcome as Dependabot / advisory links)
