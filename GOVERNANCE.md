# Governance

Klados aims for open, community-governed stewardship as described in the [Platform Bible](https://limitlesslearning.github.io/docs/). Governance matures with the roadmap phases.

## Phase 0 — Documentation (current)

| Role | Who |
| --- | --- |
| Founder-maintainer | [@capsmagick](https://github.com/capsmagick) |

In Phase 0 the founder-maintainer:

- Owns repository access, releases, and merge authority
- Triages the [project board](https://github.com/orgs/limitlesslearning/projects/1)
- Records locked decisions in the [Decision log](https://limitlesslearning.github.io/docs/decisions/)
- Appoints triagers and reviewers as the community grows

## Path to community governance

Per the manifesto and Platform Bible governance section:

1. **Phase 0–1** — Maintainer-led decisions; community proposals via RFCs and PRs.
2. **Phase 2+** — Expand reviewer/moderator hierarchy; documented standards maintenance.
3. **Later phases** — Broader community and economy-aligned governance (including future DAO-style mechanisms where appropriate). Timing and mechanics will be recorded as locked decisions — not assumed here.

Stub sections in the Bible that still say *needs drafting* are open questions, not policy.

## Roles

| Role | Responsibilities | How you get there |
| --- | --- | --- |
| **Contributor** | Opens issues/PRs; follows CoC and CONTRIBUTING | Anyone who participates |
| **Triager** | Labels, prioritizes, requests info, routes duplicates; may assign `good first issue` | Appointed by a maintainer after consistent helpful triage |
| **Reviewer** | Reviews PRs for correctness, scope, licensing, and docs quality; may request changes | Appointed by a maintainer after quality reviews |
| **Maintainer** | Merge authority, security response, governance updates, Decision log | Appointed by existing maintainers; Phase 0: founder-maintainer |

Role badges in GitHub (triage/write/maintain) are granted to match these responsibilities.

## Decision process

1. Open an **RFC / decision proposal** issue (or PR that updates docs).
2. Discuss in the issue/PR until trade-offs are clear.
3. Maintainer records the outcome in the [Decision log](https://limitlesslearning.github.io/docs/decisions/).
4. Locked decisions are **not reopened** unless new evidence appears; supersede with a new log entry that references the old `#`.

Day-to-day product and docs changes use normal PR review; only cross-cutting or irreversible choices need the Decision log.
